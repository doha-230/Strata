압축 해제 → GGUF 두 파일 복사 → RUN.bat 실행

NVIDIA RTX A6000 48GB VRAM, RAM 64GB, 폐쇄망 Windows PC에서 원본 Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS를 이미지 입력과 MTP까지 켜고 사용하는 방법입니다.

Windows 10/11인터넷 없이 설치이미지 입력 켜짐MTP 켜짐32K 컨텍스트
목차 먼저 할 일PC 조건파일 넣는 곳실행과 확인채팅·이미지·APIVRAM·RAM·SSD설정 바꾸기문제 해결구성·검증

먼저 할 일: 세 단계

패키지에는 실행에 필요한 프로그램, Python, CUDA 라이브러리, 이미지 가중치와 MTP가 들어 있습니다. 빠진 것은 메인 LLM GGUF 두 파일뿐입니다.

  1. ZIP 압축 풀기

    SSD의 NTFS 드라이브에 strata-win-a6000-iq3_xxs-vision 폴더가 생기도록 풉니다.

  2. GGUF 두 파일 복사

    아래의 정확한 이름을 가진 파일을 압축 해제한 폴더의 models에 넣습니다.

  3. RUN.bat 실행

    첫 실행은 GGUF를 확인하고 pack과 토크나이저를 만듭니다. 준비가 끝나면 브라우저에서 로컬 주소가 열립니다.

폐쇄망에서 추가 다운로드 없음

모델 두 파일과 NVIDIA 드라이버가 이미 준비되어 있으면 Python이나 CUDA Toolkit을 따로 설치하지 않습니다.

PC 조건

48GB VRAMNVIDIA RTX A6000 · GPU 0번 사용
64GB RAMIQ3_XXS 전문가 가중치가 주로 상주
85GB 이상모델 복사와 첫 준비를 위한 SSD 여유 공간 권장
  • Windows 10/11, AVX2를 지원하는 x64 CPU가 필요합니다.
  • NVIDIA 드라이버 580 이상이 설치되어 있어야 합니다. 드라이버는 패키지에 들어 있지 않습니다.
  • RAM 64GB에서는 큰 프로그램을 함께 켜면 메모리 여유가 작아질 수 있습니다.

이 ZIP은 Linux에서 조립하고 압축 무결성을 검사했습니다. Windows A6000 실기기에서의 실행은 아직 검증하지 못했습니다.

GGUF는 어디에 넣나요?

압축 해제한 폴더 바로 아래의 models 폴더입니다. 원본 ISTA-DASLab의 GSQ-RCO IQ3_XXS 두 조각을 원래 이름 그대로 넣으세요.

strata-win-a6000-iq3_xxs-vision\
├─ RUN.bat
├─ MANUAL.html                    ← 지금 읽는 설명서
├─ models\
│  ├─ Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-00001-of-00002.gguf  ← 직접 복사
│  ├─ Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-00002-of-00002.gguf  ← 직접 복사
│  └─ mmproj-Qwen3.8-Flash-Next-BF16.gguf              ← 이미 포함
├─ mtp\rt\                        ← 이미 포함
├─ engine\                        ← 이미 포함
└─ python\                        ← 이미 포함
이름이 비슷한 다른 모델은 사용할 수 없습니다.

이 패키지의 준비 스크립트는 원본 GSQ-RCO IQ3_XXS용입니다. Unsloth 또는 OrcaRouter GGUF와 섞지 마세요. mmproj 파일도 지우거나 교체하지 마세요.

메인 GGUF 두 조각은 합계 약 76GB입니다. 별도 packs\iq3_xxs 폴더는 첫 실행에서 자동 생성됩니다.

실행과 확인

  1. 탐색기에서 RUN.bat을 두 번 클릭합니다. 검은 창을 닫으면 서버도 종료됩니다.
  2. 첫 실행은 GGUF 검사와 pack 생성 뒤에 이미지 인코더와 모델을 불러옵니다. 시작 중 메모리 사용량이 크게 올라갈 수 있으니 완료 메시지까지 기다립니다.
  3. 브라우저에서 http://127.0.0.1:8080/health를 열어 "loaded": true와 "images": true를 확인합니다.
  4. http://127.0.0.1:8080에서 채팅을 시작합니다.

PowerShell에서도 확인할 수 있습니다.

Invoke-RestMethod http://127.0.0.1:8080/health

서버는 기본적으로 이 PC에서만 접속 가능한 127.0.0.1:8080에 열립니다. 다른 장치에 공개하려면 API 키 설정이 반드시 필요합니다.

채팅, 이미지, 앱 연결

브라우저

http://127.0.0.1:8080에서 채팅합니다. 이미지 파일을 넣으면 포함된 mmproj와 GPU 이미지 인코더가 처리합니다. 이미지 한 장은 최대 1,024 이미지 토큰으로 설정되어 있습니다.

다른 앱의 API 주소

연결 방식주소메모
OpenAI 호환http://127.0.0.1:8080/v1앱의 Base URL에 입력
Anthropic 호환http://127.0.0.1:8080/v1/messages로컬 메시지 API
상태 확인http://127.0.0.1:8080/health로딩 완료 여부 확인

기본 설정에는 API 키가 없지만 서버가 로컬 PC에서만 수신합니다. 앱이 API 키 입력을 요구하면 로컬 연결에는 임의 문자열을 넣을 수 있습니다.

VRAM·RAM·SSD에는 무엇이 놓이나요?

각 장치에 모델을 딱 한 번씩 나누어 저장하지 않습니다. VRAM 전문가 캐시는 RAM에 있는 전문가의 사본입니다. 아래는 현재 32K·이미지·MTP 설정의 예상이며, 실제 수치는 시작할 때 정해집니다.

장치현재 동작크기와 주의점
VRAM 48GB기본 가중치, MTP, KV 캐시, GPU 이미지 인코더와 자주 쓰는 전문가 캐시이미지 및 이후 작업을 위해 700MiB를 예약합니다. 전문가 캐시는 남는 VRAM에 맞춰 자동 결정됩니다.
RAM 64GBIQ3_XXS 전문가 가중치 전체와 실행 데이터전문가 약 43GB와 기타 약 6GB. VRAM에 있는 전문가도 RAM 사본이 유지됩니다.
SSD메인 GGUF, 프로그램, MTP·이미지 파일, 생성된 pack모델 약 76GB. 그 안의 약 29GB PLE 조회 테이블은 SSD에 남아 필요한 부분을 읽습니다.
실제 사용량 보기

웹 앱의 About → Experts in VRAM에서 GPU 전문가 캐시를 확인할 수 있습니다. http://127.0.0.1:8080/metrics의 engine.expert_cache_mib와 engine.arena_mib에는 실제 시작 결과가 표시됩니다.

기본 설정에는 SSD에서 전문가를 계속 읽는 저 RAM 모드가 켜져 있지 않습니다. VRAM에 없는 전문가는 주로 RAM에서 계산합니다.

나중에 설정 바꾸기

strata-iq3_xxs.json을 직접 고쳐도 유지되지 않습니다.

RUN.bat이 매번 prepare.py를 실행해 JSON을 다시 만듭니다. 변경은 압축 해제한 폴더의 prepare.py에서 한 뒤 RUN.bat을 재실행하세요.

바꾸려는 것prepare.py에서 찾을 값현재 값
대화 길이"--max-context", "32768"32K 토큰
KV 캐시 형식"--kv", "int8"8비트
MTP 단계"--spec", "4"4
VRAM 예약"--vram-reserve-mib", "700"700MiB
이미지 토큰 상한"max_tokens": 10241,024
GPU 번호"gpu": 00번

예: 다른 프로그램을 위해 VRAM을 더 남기려면 "--vram-reserve-mib", "700"을 "--vram-reserve-mib", "2048"로 바꿉니다. 그만큼 GPU 전문가 캐시가 줄 수 있습니다.

포트 8080을 바꾸고 싶다면

prepare.py의 "port": 8080과 RUN.bat의 --port 8080을 같은 숫자로 바꿉니다. RUN.bat의 명령줄 값이 서버 실행에 쓰이므로 둘 다 바꿔야 합니다.

RAM을 줄이고 SSD에서 전문가를 읽고 싶다면

고급 옵션인 --mmap-experts를 prepare.py의 "args" 목록에 추가할 수 있습니다. 원본 GGUF를 매핑해 RAM에 전체 전문가를 복사하지 않는 대신, GPU 캐시에 없는 전문가를 SSD에서 읽을 수 있어 속도가 달라집니다. 현재 64GB RAM 설정에는 기본으로 필요하지 않습니다.

다른 양자화 모델로 바꾸고 싶다면

현재 준비 스크립트는 원본 GSQ-RCO IQ3_XXS 파일 이름, pack 경로, 프로필에 맞춰져 있습니다. GGUF만 다른 양자화로 교체하지 말고 해당 모델에 맞는 설정과 pack을 새로 준비해야 합니다.

문제 해결

보이는 현상확인할 것
“필요한 파일이 없습니다”models의 GGUF 두 파일 이름과 mmproj 존재 여부를 확인합니다.
“GGUF가 잘렸습니다”복사가 끝나지 않았을 수 있습니다. 원본 파일을 다시 복사합니다.
“NVIDIA 드라이버” 오류nvidia-smi 실행 여부와 드라이버 버전 580 이상을 확인합니다.
시작 중 RAM 부족·매우 느림큰 프로그램을 닫고 다시 시작합니다. 계속 부족하면 더 작은 모델이나 고급 저 RAM 설정이 필요할 수 있습니다.
포트 8080 사용 중이미 실행 중인 서버를 종료하거나 위의 포트 설정 두 곳을 같이 바꿉니다.
이미지 처리 오류models\mmproj-Qwen3.8-Flash-Next-BF16.gguf와 engine\strata-vision.exe가 있는지 확인합니다.

자세한 오류는 압축 해제한 폴더의 strata-iq3_xxs.log와 실행 창 마지막 줄에서 확인합니다.

패키지 구성과 검증 범위

  • 포함: Strata Windows 엔진 v0.1.38, Python 3.12, CUDA 13 런타임·cuBLAS, GPU 이미지 인코더와 mmproj, 변환된 MTP 런타임, 웹 앱.
  • 제외: 메인 LLM GGUF 두 조각, NVIDIA 시스템 드라이버.
  • 압축 파일의 내용 목록과 CRC를 검사했고, 메인 LLM GGUF가 들어 있지 않은 것을 확인했습니다. 주요 파일의 해시는 SHA256SUMS.txt에 기록되어 있습니다.

이 문서는 프로그램과 함께 저장되는 단일 HTML 파일입니다. 화면 표시·인쇄에 외부 글꼴이나 인터넷이 필요하지 않습니다. 원본 모델과 프로젝트의 상세 문서는 인터넷 연결이 가능한 PC에서 ISTA-DASLab 모델 페이지 및 Strata 저장소를 참조하세요.
